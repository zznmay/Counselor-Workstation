# 杭科院辅导员工作台 · 移动端 UI 与交互重构 —— 需求摘要

> 产出人：需求发现分析师（许明需）
> 阶段：Phase 1 / 需求发现
> 输入依据：现有代码侦察结论（React 18 + TS + AntD 5 + React Router 6 + Vite 5，11 个业务模块，「未来界面蓝」视觉体系，`useIsMobile(768)` + AntD Drawer 现状）
> 状态：**待用户确认**（用户当前不在线，本摘要中所有推断性内容均已在「§7 假设与待确认项」显式登记）

## 0. 一句话需求

把「杭科院辅导员工作台」从**桌面表格优先**的形态，重构为**移动优先、卡片化、触控友好**的形态，重点解决辅导员在手机上**「看清信息、快速办事」**两大诉求；本期**只做移动端（≤768px）高保真原型**，桌面端保持不动。

## 1. 设计需求五要素

### 维度 1 · 场景（Surface）

| 项 | 结论 | 理由 |
|----|------|------|
| 产出形态 | **移动端 Web / H5 响应式页面**（≤768px 视口），非原生 App、非小程序 | 现有工程为 Vite 打包的 React SPA，`useIsMobile(768)` 已按视口切换；沿用同一套构建与路由，成本最低、可复用登录态与后端接口 |
| 具体页面类型 | 以 **列表页 + 详情页 + 表单页** 为主，外加 **仪表盘式工作台** | 11 个模块中 7 个是「列表→详情/操作」结构（学生、谈心、预警、通知、审批、待办、模板），工作台是唯一的聚合看板 |
| 使用情境 | **碎片化、走动中使用**：办公室外、宿舍走访、会议间隙、下班后处理待办；单手操作、可能弱网 | 辅导员高频场景是「不在电脑前时的即时查看与处理」，因此首屏信息密度、单手可达性、加载鲁棒性是关键 |
| 设备预期 | 主流手机竖屏（推荐最小适配 360px 宽，基准 375–430px） | 覆盖 iPhone SE/主流 Android 小屏到旗舰大屏 |

### 维度 2 · 受众（Audience）

| 项 | 结论 | 理由 |
|----|------|------|
| 核心用户 | **高校辅导员**（含主责辅导员与共管辅导员两类角色），少量**管理员** | 系统数据按「主责辅导员 + 共管」隔离，是辅导员的自用工作台 |
| 使用目的 | 日常学生管理、心理/学业预警处置、谈心谈话记录、审批办理、通知发布、待办打卡 | 对应 11 个模块的功能落点 |
| 技术素养 | **中低**：熟练使用微信/办公类 App，但不懂设计术语；对「下拉刷新、上拉加载、底部导航」有肌肉记忆 | 因此交互必须**遵循手机通用范式**，避免自创手势与隐藏入口 |
| 使用心理 | **任务驱动、时间紧张**：打开即想「有没有要我处理的事」；对红点/预警高度敏感；担心漏办、担心操作不可逆 | 支撑「行动优先级前置、操作有确认与回执」的设计决策 |
| 数据敏感度 | **高**：接触学生手机号、家庭联系人等隐私；内网系统，合规要求严 | 移动端需默认**脱敏展示**，查看明文需显式操作 |

### 维度 3 · 调性（Tone）

- **沿用「未来界面蓝」单一视觉语言**：单色系 + 水彩晕染背景 + 分层卡片，理性、克制、专业可信，符合「校园行政工具」的身份。
- 对应视觉学派：**Modern Minimal（现代极简）为主**，叠加一丝 **Editorial 的信息层级感**（用字号/字重/留白建立主次，而非靠颜色堆砌）。
- **手机端调性微调**：相比桌面端，信息密度可略降、留白增大、圆角与阴影保持既有两档卡片阴影，**不引入新配色、不做 3D 重阴影、不做装饰性元素堆砌**（Anti-Slop）。
- **不采用**：Brutalist（与政务/校园工具的稳重气质不符）、Soft Warm 的暖色系（会破坏既有蓝系品牌一致性）。
- 理由：约束明确要求「必须延续既有视觉体系，不得重新发明」。调性工作的重点是**把桌面视觉语言正确降维到移动端**，而非改风格。

### 维度 4 · 品牌上下文（Brand Context）

| 项 | 结论 | 理由 |
|----|------|------|
| 品牌资产状态 | **已有且必须延续**——无需做品牌提取或重新选型 | 已有完整 CSS 令牌与 AntD `ConfigProvider` 主题 |
| 设计令牌（锁定，不新增主色） | `--app-primary:#5F86FF`、`--app-primary-strong:#4A6FE3`、`--app-primary-soft:#A9C2FF`、`--app-ink:#2F3E66`、`--app-ink-secondary:#5A6B8C`、`--app-border:#E7EEFB`；卡片阴影两档；body 水彩径向渐变 | 直接读取自 `src/styles/global.css` 与 `src/App.tsx`，属既有资产 |
| 语义色（AntD 主题已定义） | success `#5CA97F` / warning `#DFA050` / error `#D9645C` | 预警红/橙/黄分级应在此语义色基础上定义**三级独立令牌**，并强制「颜色 + 图标 + 文字」三重编码 |
| 品牌标识 | 侧栏 Logo「杭」字徽标 + 「杭科院 · 辅导员工作台」文字 | 移动端在顶栏/更多页/登录页沿用同一 Logo 语言 |
| 主题模式 | 需求线索称「支持亮/暗双主题」，但**当前代码仅实现亮色主题**（`App.tsx` 未接入 `theme.darkAlgorithm`，`global.css` 无 `prefers-color-scheme` / `[data-theme]` 分支） | ⚠️ 与侦察结论存在出入，已登记为**待确认项 H1**：本期移动端原型是否需交付暗色稿 |

### 维度 5 · 规模（Scale）

| 项 | 结论 | 理由 |
|----|------|------|
| 页面范围 | **本期移动端原型约 12–15 屏**（详见 §3）：布局外壳 1 + P0 核心 6–8 屏 + P1 补充 3–4 屏 + 更多页 1 | 覆盖用户点名的模块，兼顾完整性与交付节奏 |
| 页面性质 | 单页 → 多页流程（列表→详情→操作→回执），**有状态流转** | 预警有处理闭环、通知有发布状态机、审批有通过/驳回、待办有打卡 |
| 响应式 | 仅移动端断点（建议在现有 768 下**细分 576 / 768 两级**，并新增 360 最小宽度校验）；桌面布局**不得改动** | 约束要求「桌面端布局与配色不得破坏」 |
| 交互复杂度 | 中：列表加载/筛选/搜索、底部导航与二级导航、底部弹层（筛选、更多、操作确认）、下拉刷新/上拉加载、表单提交、状态徽标 | 无需复杂动画/3D；动效统一 Subtle 级 |
| 数据规模假设 | 单辅导员名下学生量级假设为**数十至数百**，预警/待办为**个位到数十条** | 决定列表用「上拉分页」而非一次全量；已登记待确认 H6 |

## 2. 移动端信息架构（IA）

### 2.1 现状问题

桌面端侧边栏含 **9 个一级项 + 2 个二级组（工具、系统管理）**，移动端把整棵菜单塞进 `Drawer(width 248)`。问题：① 一级项 >5，无法直接映射到底部导航；② 层级靠抽屉，高频功能需「开抽屉→找→点」三步；③ 列表页仍是 AntD `Table` + 分页器（`scroll-x` 横向滚动），与移动端手势范式冲突。

### 2.2 一级导航取舍（底部导航）

**硬约束：底部导航项 ≤5，超出走「更多」。**

**推荐方案（主推）——4 个业务常驻 + 1 个「更多」**

| 槽位 | 名称（沿用既有语义） | 路由 | 徽标 | 定位 |
|------|----------------------|------|------|------|
| 1 | **工作台** | `/` | 汇总角标 | 打开即看的「今日全景与行动入口」 |
| 2 | **学生管理** | `/students` | — | 最高频的身份化查询入口 |
| 3 | **预警管理** | `/warnings` | 未解除预警数 | 安全红线，必须一键可达 |
| 4 | **待办提醒** | `/todos` | 今日待办数 | 行动闭环的落脚点 |
| 5 | **更多** | 打开「更多」页/底部弹层 | 汇总角标 | 收纳其余功能（见 2.3） |

**分层理由**
- **工作台**：唯一的聚合看板，天然是「移动端首页」，承载问候、关键数据、预警名单、今日待办、待审批、类型分布。
- **学生管理**：辅导员最高频的「查人」入口（查电话、查班级、查是否被预警）。
- **预警管理**：红/橙/黄三级风险涉及学生安全，属**不可下沉**的常驻项。
- **待办提醒**：与预警同属「行动闭环」，两者常驻可形成「发现问题 → 打卡闭环」的动线。
- **审批中心**：虽然重要且日常，但**已在工作台以聚合卡直连**，且可通过「更多」一步到达，故本方案将其放入「更多」首位。

> ⚠️ **取舍待确认（H2）**：第 4 槽在「待办提醒」与「审批中心」之间存在竞争。备选方案：将第 4 槽替换为「审批中心」，待办并入工作台聚合卡 + 更多。需用户拍板。

### 2.3 下沉功能收纳（「更多」页）

「更多」页采用**网格化功能宫格**（沿用既有 Menu/图标体系，AntD 图标，**不用 emoji**）：

- 一级直达：**审批中心** `/approvals`、**谈心谈话** `/conversations`、**通知发布** `/notices`
- 资料类：**模板汇总库** `/templates`、**实用工具** `/tools`
- 管理类（仅 `role==='admin'`）：**用户管理** `/admin/users`、**访问日志** `/admin/logs`

**共同点**：这些功能**使用频率低于四大常驻项**，或**更适合桌面完成**（如模板批量下载、Excel 拆分合并等 iframe 工具），下沉到「更多」不会显著增加高频操作成本。

### 2.4 二级导航与路由不变

- **不改路由 slug、不改一级导航名称语义**（约束），仅新增移动端**呈现层外壳**：底部 TabBar + 顶栏（返回/标题/操作）+ 可选分段控件。
- **学生详情、审批详情、谈心详情等**为二级页面：从列表进入，移动端优先**全屏页 + 顶部返回**（而非桌面 Drawer，避免小屏遮挡）。
- **工具内部页** `/tools/:toolKey`（iframe 内嵌）保持路由不变；移动端在「更多→实用工具」进入，需评估 iframe 在小屏的可用性（见 H5）。

### 3.1 关键交互流程（原型需体现的动线）

1. **预警处置闭环**：工作台预警卡 → 预警列表（筛红/橙/黄）→ 预警详情 → 记录处理措施 → 确认销号 → 返回列表状态更新（徽标联动）。
2. **学生检索→联络**：学生列表 → 搜索/筛选 → 学生卡 → 详情 → 一键拨号/发起谈心 → 回到列表。
3. **审批批办**：工作台待审批卡 → 审批列表 → 详情 → 通过（/驳回+意见）→ 回执 Toast → 列表状态更新。
4. **待办打卡**：待办列表 → 点击完成 → 打卡动画（Subtle）→ 逾期项高亮 → 已完成折叠。
5. **通知发布状态机**：草稿 → 发布 → 撤回，每步均有明确状态与二次确认（不可逆操作）。

## 4. 卡片化策略

> 原则：**卡片 = 一个可独立理解、可独立操作的信息单元**；卡内用**字号 / 字重 / 间距**建立主次，不靠加色块；同一列表内卡片结构一致，降低认知成本。

### 4.1 哪些信息进卡片

| 模块 | 卡片形态 | 首屏（主）字段 | 次级字段 | 操作区 |
|------|----------|----------------|----------|--------|
| **学生** | 学生信息卡（列表项 & 详情头） | 姓名 · 学号 · 班级/专业 · 主责/共管标识 · **预警状态（若有：颜色+图标+文字）** | 最近谈心时间、宿舍、辅导员 | 电话 / 消息（≥44px 热区） |
| **预警** | 预警卡 | 学生姓名 · **级别（红/橙/黄 三编码）** · 事由摘要 · 发生时间 · 处理状态 | 跟进人、截止时间 | 进入处置 / 一键销号 |
| **待办** | 待办卡 | 事项标题 · **优先级** · 截止时间（逾期高亮） | 关联学生、来源 | 打卡完成 |
| **审批** | 审批卡 | 事项名称 · 申请人 · 类型 · 提交时间 · 状态 | 摘要、附件数 | 去审批 |
| **工作台数据卡** | 指标卡 | 大数字 + 名称 | 环比/副标题 | 点击跳转 |
| **谈心** | 记录卡 / 时间线节点 | 学生 · 主题 · 时间 | 摘要、记录人 | 查看/编辑 |
| **通知** | 通知卡 | 标题 · 状态徽标（草稿/发布/撤回）· 置顶标识 | 发布范围、时间、阅读数 | 查看/编辑/撤回 |

### 4.2 学生卡片字段层级（重点，用户点名「学生信息卡片化」）

- **第一层（首屏必读，最大字号/最高对比）**：**姓名**、**班级/专业**、**主责/共管标识**。
- **第二层（一眼可见）**：**预警状态**（仅在有预警时出现，含颜色+图标+文字）、学号、最近一次谈心时间。
- **第三层（可折叠/详情内）**：宿舍、辅导员、**手机号与家庭联系人（默认脱敏，点击「查看」后显式展示，防截屏外泄）**。
- **快捷操作**：电话、消息、发起谈心、标记预警——**触控热区 ≥44×44px，间距 ≥8px**。
- 理由：辅导员查学生的第一诉求是「这是谁、哪个班、归不归我、有没有风险」；隐私字段属低频且敏感，需二次操作。

### 4.3 卡片通用规范

- 单一卡片内**视觉层级不超过 3 层**；主信息字号明显大于次信息（建议主 16–17px / 次 13–14px，具体由设计系统阶段定稿）。
- 卡片圆角、两档阴影**沿用既有令牌**（`--app-card-shadow` / `--app-card-shadow-hover`），移动端可只保留一级阴影（去掉 hover）。
- 状态一律**颜色 + 图标 + 文字三重编码**（满足「不得仅用颜色传达状态」）。
- 列表卡片可整卡点击进入详情；卡内快捷按钮需阻止冒泡，避免误触（热区间距 ≥8px）。

## 5. 硬性设计约束（写入摘要，供设计系统与原型阶段强制执行）

**触控**
- 交互元素热区 **≥44×44px**；相邻可点元素间距 **≥8px**。

**可访问性**
- 正文文字对比度 **≥4.5:1**；状态**不得仅用颜色**传达——预警红/橙/黄必须同时带**文字或图标**。

**布局**
- **移动优先**，**禁止横向滚动**（替代现有 AntD Table 的 `scroll-x`）；
- 视口高度用 **`100dvh`**（不用 `100vh`）；
- 适配安全区：`env(safe-area-inset-top / bottom / left / right)`（刘海、底部小黑条）。

**导航**
- 底部导航项 **≤5**，超出走「更多」。

**动效**
- **Subtle 级**：250–350ms，仅用 `transform` / `opacity`；
- 必须尊重 **`prefers-reduced-motion`**（关闭动效时状态仍可感知）。

**反模式（Anti-Slop，禁止）**
- 不用 emoji 当图标（统一用 AntD 图标 / 统一图标集）；
- 不做 3D 重阴影；
- 不做纯装饰性元素堆砌。

## 6. 本期范围边界

| 边界 | 说明 |
|------|------|
| **只做移动端** | 设计仅覆盖 **≤768px**；**桌面端（>768px）布局与配色一律不动** |
| **路由与命名受保护** | 不改变路由 slug（`/students`、`/warnings`…）与一级导航名称语义，保护既有使用习惯 |
| **不改后端** | 不新增接口、不改数据模型与权限模型（主责/共管隔离、管理员角色保持） |
| **不重新发明视觉** | 延续「未来界面蓝」令牌与两层卡片阴影，移动端只做正确的降维 |
| **流程闸门** | **先出高保真原型 → 用户确认 → 再进入代码开发**；确认前不产出可运行代码 |
| **不在本期** | 不做 PWA / 离线、不做原生 App、不做推送通道（除非 H7 确认需要） |
