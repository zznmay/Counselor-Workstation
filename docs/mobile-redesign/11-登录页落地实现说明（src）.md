## 2. 实现要点

### 2.1 视口分发（沿用项目既有约定）

```tsx
export default function Login() {
  const isMobile = useIsMobile();
  return isMobile ? <LoginMobile /> : <LoginDesktop />;
}
```
与 `students / todos / dashboard` 等页面完全同构；桌面端代码路径零改动（已实测：≥769px 时 `.lg-card` 不存在、原 `.ant-card` 登录卡片正常）。

### 2.2 局部缩放单位 `--u`（不污染全局根字号）

原型靠 `html{font-size:100vw/43.2}` 做等比缩放，但项目里改根字号会影响全站。因此改为**局部单位**：

```css
.lg-page{
  --u: min(calc(100vw / 43.2), calc(100vh  / 76.8), 10px);  /* 兜底 */
  --u: min(calc(100vw / 43.2), calc(100dvh / 76.8), 10px);  /* 支持 dvh 时覆盖 */
}
```
所有尺寸写 `calc(N * var(--u))`，与原型 `N rem` 等价。432px 视口下 1u = 1 设计 px。
高度项 `100dvh/76.8` 是矮视口兜底：视口比 9:16 更矮时整体再缩一档，保证整屏容纳。

居中用 `.lg-card{margin:auto}` 而非 `align-items:center` —— 后者在内容高于视口时会「顶部被裁且无法触达」。

### 2.3 逻辑复用（与桌面端同源，未新增/删减任何业务约束）

| 能力 | 实现 |
|---|---|
| 校验 | 用户名空 → `请输入用户名`；密码空 → `请输入密码`（与桌面端文案一致） |
| 提交 | `POST /api/auth/login`，body `{ username, password }` |
| 错误提示 | `message.error(服务端 message)` |
| 成功提示 | `message.success('欢迎，' + displayName)` |
| 跳转 | `navigate('/', { replace: true })` |
| 会话保持 | `setSession(token, user)` → `localStorage` |
| 首次登录改密 | `mustChangePassword` → 切改密态 → `POST /api/auth/change-password`，body `{ oldPassword, newPassword }` |
| 改密校验 | ≥8 位 / 含字母和数字 / 两次一致，文案与桌面端逐字一致 |
| 密码可见性 | `type` 切换 + `aria-pressed` / `aria-label` 同步 |
| 回车提交 | 真实 `<form onSubmit>` |

改密态复用同一套「两输入框 + 胶囊按钮」骨架：标题→`设置新密码`，副标题→`当前账号：…（…）`+ 规则说明，字段→新密码/确认新密码，按钮→`设置并进入系统`，并隐藏协议行（与桌面端改密表单一致）。

## 3. 有意偏差（3 处，均可一行改回）

1. **品牌文案**：原型（及参考图）为占位文案「知行 / 以知润心 以行育人 / 知行合一 · 育见未来」。实装改用杭科院真实表述 ——
   品牌行 `杭科院 + 辅导员工作台`，头图大标题取**校训「德业兼修 / 知行合一」**（4+4，与原型版式完全吻合），副标题取**学校精神「爱满天下 · 立德树人」**，面板副标题 `杭科院辅导员工作台`。
   校训/学校精神已核对学校官网 `hzpt.edu.cn`。
   若要逐字回到参考图，改 `mobile.tsx` 顶部 `COPY` 常量的三个字段即可。
2. **品牌标**：原型用参考图的 logo 位图；实装改用全站统一的「杭」渐变徽标（与 `.tb-logo`、桌面登录徽标同一语言），避免把参考图的品牌图形带进生产系统。
3. **输入框字号 16px**（原型 10.5px）：低于 16px 时 iOS Safari 聚焦会强制放大页面；同时对齐项目令牌 `--fs-input:16px`。这是相对原型唯一的功能性偏差。
   配套：输入/按钮高度给 `40px` 下限，避免窄屏等比缩小后触控区过小（432 基准下仍为设计值 40.5 / 41）。

另外头图仍沿用参考图照片。注意 `05-登录页需求摘要.md` 曾记录「规避虚构校园形象风险」的早期决策；若需要，`login-mobile.css` 中把 `.lg-hero` 的 `background` 换成 `--m-grad-hero` 渐变即可，其余版面不受影响。

## 4. `src/api/request.ts` 的一处可选开关（重要）

错口令时服务端返回 **401**，`request()` 原逻辑先 `clearAuth()` 再 `window.location.href='/login'` —— 整页 reload，错误提示来不及渲染，用户只看到「页面闪一下、什么也没说」。

处理：新增**默认关闭**的 `skipAuthRedirect`，仅登录类接口显式开启：

```ts
if (res.status === 401 && !skipAuthRedirect) { clearAuth(); location.href='/login'; throw new Error('登录已过期，请重新登录'); }
throw new Error(message);   // 401 且 skip 时：抛出服务端原文「用户名或密码错误…」
```

- 默认路径（其余所有页面）行为与改动前**逐行一致**，无影响；
- 登录页开启后，错口令就地提示并停留原页。

## 6. 如何验证登录功能正常

```bash
# 1) 类型检查 + 构建
cd <项目根>
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build

# 2) 起本地服务端（托管 dist + /api）
cd server && PORT=8444 node --experimental-sqlite index.js
# 浏览器打开 https://localhost:8444/login （自签证书，需忽略警告）
```

| 验证项 | 操作 | 预期 |
|---|---|---|
| 移动端呈现 | 浏览器 DevTools 切 390×844（或手机访问） | 出现头图 + 非对称圆角白面板的新登录页；桌面宽度下仍是原 AntD 卡片 |
| 空校验 | 直接点「登录」 | 提示「请输入用户名」 |
| 口令校验 | 只填用户名后点「登录」 | 提示「请输入密码」 |
| 错口令 | 填错密码点「登录」 | 提示「用户名或密码错误（再错 N 次将锁定）」，**页面不跳转** |
| 登录成功 | 用未改密账号（如 `zhenann / Hzky@123456`）登录 | 提示「首次登录请先设置新密码」→ 进入改密态 |
| 改密规则 | 新密码填 `abc` / `abcdefgh` / 两次不同 | 分别提示「至少 8 位」「需同时包含字母和数字」「两次输入的新密码不一致」 |
| 改密成功 | 填符合规则的相同密码 | 「密码已更新，欢迎加入！」→ 跳首页 |
| 会话保持 | 刷新页面 | 仍停留在首页（localStorage `workbench_token` 存在） |
| 密码可见性 | 点右侧眼睛 | `type` 在 password / text 间切换 |
| 适配 | 320 / 375 / 390 / 430 宽度 | 无横向滚动、无纵向滚动，输入框点得动、按钮可点 |

> 提醒：服务端有「连错 5 次锁定 15 分钟」的保护，压测错误口令请用请求拦截（桩），或事后清理 `server/data/app.db` 的 `loginAttempts` 表。
