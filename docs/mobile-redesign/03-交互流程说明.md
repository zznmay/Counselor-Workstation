# 杭科院辅导员工作台 · 移动端交互流程说明

> 产出人：原型构建师（筑原型）
> 阶段：Phase 2 / 原型配套说明
> 配套文件：`02-设计令牌.md`（取值）、`prototype/index.html`（8 屏高保真原型）
> 说明范围：本文描述**当前原型已覆盖到的交互与状态**；未覆盖的 P1/P2 流程只标注入口，不展开

## 0. 如何在原型里「走流程」

`prototype/index.html` 为纯静态单文件，**无 JS 业务逻辑**，状态流转全部用纯 CSS 表达。评审时按下面方式操作即可看到状态变化：

| 想看的流程 | 在原型里点哪里 | 会看到什么 |
|---|---|---|
| 筛选弹层开合 | 屏 02 顶部的「筛选」按钮；屏 03 默认展开 | 遮罩淡入 + 抽屉从底部滑入（240ms） |
| 脱敏查看 | 屏 04「本人手机 / 父亲 / 母亲」行的「查看」按钮 | 掩码 `158****1094` → 明文 `158 8872 1094`，按钮变「隐藏」，行底出现黄色提示 |
| 待办打卡 | 屏 06 任意待办左侧的 44px 方框 | 勾选后标题划线降权、卡片淡出（表示已完成） |
| 已完成折叠 | 屏 06 底部「已完成 2 项」 | `<details>` 展开/收起，箭头旋转 |
| 审批列表 → 详情 | 屏 07 首张卡的「去审批」 | 列表隐藏、详情滑入；详情内「返回」回到列表 |
| 驳回必填意见 | 屏 07 详情里切换「通过 / 驳回」单选 | 选「驳回」展开意见框并常驻显示错误提示；选「通过」隐藏该字段与错误 |
| 预警销号闭环 | 屏 05 李昊然卡的「确认销号」→ 弹窗「确认解除」 | 卡片状态「处理中 → 已解除」、转虚线框、红色色条转绿、销号按钮消失、顶部 Toast 回执 |

> 原型中的安全区用 `max(44px, env(...))` 模拟 iPhone X 级刘海与底部小黑条；生产环境直接换回 `env(safe-area-inset-top / bottom)`。

## 1. 关键流程一 · 预警处置闭环（P0）

**目标**：把「发现风险 → 处置 → 留痕 → 销号 → 统计更新」串成一条可在手机上单手完成的动线。

**原型对应**：屏 01（工作台预警名单卡）→ 屏 05（预警管理）→ 屏 05（处置 / 销号）

| 步 | 角色动作 | 界面反馈 | 状态迁移 |
|---|---|---|---|
| 1 | 在工作台看到「预警名单」卡，卡上直接显示前 3 条与级别 | — | — |
| 2 | 点卡片右上「全部 7 ›」或底部 Tab「预警管理」 | 进入 `/warnings`，顶部出现级别筛选 chip | — |
| 3 | 点级别 chip（红色 1 / 橙色 3 / 黄色 5） | chip 变主色底纹，列表按级别过滤 | 筛选态 |
| 4 | 点橙色卡「去处置」 | 进入预警详情（原型以卡内展开表示） | `待处理 → 处理中` |
| 5 | 填「处理措施」并提交 | 卡内出现灰色措施块；按钮变「继续跟进」 | `处理中`，写入 `handleNote` |
| 6 | 点击「确认销号」 | **弹出居中二次确认**：「解除后将不再计入未解除统计，且不可恢复」 | 阻塞，等待确认 |
| 7 | 点「取消」 | 关闭弹窗，状态不变 | — |
| 8 | 点「确认解除」 | ① 顶部 Toast「预警已解除」2.6s；② 卡片转虚线框 + 绿色「已解除」；③ 销号按钮消失；④ 顶部统计「未解除 7 → 6」；⑤ TabBar 角标 7 → 6 | `处理中 → 已解除` |

**状态机（预警）**

```
待处理 ──记录措施/去处置──▶ 处理中 ──确认销号(二次确认)──▶ 已解除
   │                          │
   └────────── 直接销号 ──────┘
已解除 = 终态（不可回退）
```

**规则**
- 已解除卡用**虚线边框 + 去阴影 + 绿色 tag**，与有内容卡明确区分（参考规范 2.8 空态纪律）。
- 级别一律「底色 + 图标 + 文字」三重编码：红色=三角警示、橙色=圆形感叹、黄色=旗帜。
- 未解除数 = `待处理 + 处理中`，驱动 TabBar 角标与工作台数据卡。

## 2. 关键流程二 · 学生检索 → 联络（P0）

**目标**：辅导员在走廊/宿舍现场用最短路径「找到这个人 → 打通电话 → 留下记录」。

**原型对应**：屏 02（列表 + 搜索）→ 屏 03（筛选抽屉）→ 屏 04（详情 + 操作条）

| 步 | 角色动作 | 界面反馈 |
|---|---|---|
| 1 | 底部 Tab「学生管理」，顶部搜索框常驻 | 列表默认按班级分组展示 |
| 2a | 在搜索框输入姓名/学号/班级（≥16px，不触发 iOS 缩放） | 输入即过滤，防抖 300ms |
| 2b | 点「筛选」 | 底部抽屉滑入（圆角 22px + 把手 + 遮罩） |
| 3 | 在抽屉里选年级 / 专业 / 班级 / 预警状态 / 在读状态 | chip 变主色底纹；多选即时生效 |
| 4 | 点「重置」清空条件，或点「确定」应用 | 抽屉落下（离场 160ms，快于入场 240ms） |
| 5 | 列表顶部显示「共 N 名 · 主责 X / 共管 Y」 | 结果即时收敛；上拉分页加载 |
| 6 | 点学生卡任意位置（卡内按钮除外） | 进入 `/students/:id` 全屏详情，顶栏带返回 |
| 7 | 在详情底部操作条点「拨号 / 短信 / 发起谈心 / 发通知 / 标记预警」 | 拨号唤起 `tel:`；谈心/通知跳对应表单并预填学生 |
| 8 | 需要明文手机号时点「查看」 | 掩码 → 明文；**离开页面自动回隐** |

**卡内按钮防误触**：整卡可点进详情，卡内「电话 / 短信」按钮必须 `event.stopPropagation()`，两按钮间距 ≥8px。

## 3. 关键流程三 · 审批批办（P0）

**目标**：移动端快速批办，且「驳回」必须留下可追溯的意见。

**原型对应**：屏 01（待审批卡）→ 屏 07（审批中心）→ 屏 07（详情）

| 步 | 角色动作 | 界面反馈 | 状态迁移 |
|---|---|---|---|
| 1 | 工作台「待审批」卡看到前 2 条 + 「共 3 项」 | — | — |
| 2 | 点卡片 →「更多」页「审批中心」（角标 3） | 进入 `/approvals`，chip：待审批 3 / 已通过 / 已驳回 | — |
| 3 | 点某张卡的「去审批」 | **全屏详情页**（移动端不用 Drawer，避免小屏遮挡）；顶栏返回 | — |
| 4 | 阅读申请内容（摘要 / 起止 / 附件 / 说明） | — | — |
| 5a | 选「通过」→「提交审批结果」 | Toast「已通过」；列表该项移入「已通过」，角标 3 → 2 | `待审批 → 已通过` |
| 5b | 选「驳回」 | 展开「驳回意见 *」文本域，`.form-err` 常驻占位 | — |
| 6b | 意见为空直接提交 | 就近红字「请填写驳回意见（必填）」，**不跳页、不抖动**（`.form-err` 保留 18px） | 校验失败 |
| 7b | 填写 ≥5 字后提交 | Toast「已驳回」；列表该项移入「已驳回」 | `待审批 → 已驳回` |

**状态机（审批）**

```
待审批 ──通过──▶ 已通过（终态）
   └──驳回(意见必填)──▶ 已驳回（终态）
```

**规则**：通过/驳回后不可再编辑；提交中按钮禁用 + 文案切换为「提交中…」，防重复提交。

## 4. 关键流程四 · 待办打卡（P0）

**目标**：把「今日事项」变成一次点击就能划掉的动作，逾期项不能被忽略。

**原型对应**：屏 01（今日待办卡）→ 屏 06（待办提醒）

| 步 | 角色动作 | 界面反馈 |
|---|---|---|
| 1 | 底部 Tab「待办提醒」（角标 = 今日未完成数） | 分三组展示：已逾期 / 今天 / 未来 |
| 2 | 看到逾期组：红色描边卡 + 「已逾期 1 天」**文字标识** | 不依赖颜色单独传达 |
| 3 | 点待办左侧 44px 方框（打卡） | 勾选动画 ≤200ms；标题划线、卡片降权；顶部 Toast「待办已完成」 |
| 4 | 完成后该项移入底部「已完成 N 项」折叠区 | `<details>` 折叠，summary 热区 44px |
| 5 | 展开折叠区可撤销 | 取消勾选 → 回到原分组 |
| 6 | 今日全部完成后 | TabBar 角标归零；工作台「今日待办」卡显示正向空态（绿色 + 图标，非灰色） |

**规则**
- 优先级沿用「高 / 中 / 低」文字标签 + 颜色，不靠颜色单编码。
- 逾期必须同时给出**文字**（「已逾期 N 天」）与**原定时间**。
- 打卡热区 ≥44×44，与相邻卡片间距 ≥8px。

## 5. 关键流程五 · 通知发布状态机（P1，原型仅覆盖到入口）

**说明**：本期原型**未包含通知列表/编辑屏**（属 P1-2），此处只固化状态机，供后续补屏时直接落位。

| 步 | 角色动作 | 界面反馈 | 状态迁移 |
|---|---|---|---|
| 1 | 「更多」→「通知发布」 | 进入 `/notices`，列表卡带状态 tag | — |
| 2 | 新建通知（标题 / 类型 / 范围 / 内容 / 置顶开关） | 草稿自动保存（防丢） | `— → 草稿` |
| 3 | 点「发布」 | 二次确认「发布后将推送给 X 名学生在读回执」 | 阻塞 |
| 4 | 确认发布 | 写入 `publishAt`；Toast「已发布」 | `草稿 → 已发布` |
| 5 | 点「撤回」 | **不可逆二次确认**（danger） | 阻塞 |
| 6 | 确认撤回 | Toast「已撤回」；卡片转中性虚线态 | `已发布 → 已撤回` |
| 7 | 撤回后可「编辑后重发」 | 回到草稿编辑 | `已撤回 → 草稿` |

**状态机（通知）**

```
   ┌──────────── 编辑 ────────────┐
   ▼                              │
草稿 ──发布(二次确认)──▶ 已发布 ──撤回(不可逆·二次确认)──▶ 已撤回
                            ▲                                │
                            └────────── 重新发布 ────────────┘
```

**规则**：发布与撤回都是**不可逆感知**的操作，必须 `confirmDialog`；撤回后原内容保留，不丢失。

## 6. 底部导航取舍理由

**硬约束**：底部导航 ≤5 项；不改路由 slug、不改一级导航名称语义；桌面端不受影响。

| 槽 | 名称 | 路由 | 角标 | 取舍理由 |
|---|---|---|---|---|
| 1 | 工作台 | `/` | — | 唯一聚合看板，天然是移动端首页；承载问候、关键数据、预警名单、今日待办、待审批 |
| 2 | 学生管理 | `/students` | — | 辅导员**最高频**的「查人」入口（查电话、查班级、查是否被预警） |
| 3 | 预警管理 | `/warnings` | 未解除数 | 红/橙/黄三级涉及学生安全，属**不可下沉**的常驻项 |
| 4 | **待办提醒** | `/todos` | 今日未完成数 | 与预警同属「行动闭环」，两者常驻形成「发现问题 → 打卡闭环」的动线 |
| 5 | 更多 | 宫格页 | 汇总角标 | 收纳审批中心、谈心谈话、通知发布、模板汇总库、实用工具 + 管理员项 |

**为什么第 4 槽是「待办提醒」而不是「审批中心」**（用户已拍板）

1. **频率与时效**：待办是「每天都有、且当天到期」的高频动作；审批是「来了才办」，且事件驱动。
2. **动线闭合**：预警（发现问题）与待办（闭环打卡）放在相邻槽位，形成「3 → 4」的一气呵成的动作序列；审批插在中间会打断这条动线。
3. **审批并未被牺牲**：① 工作台有独立的「待审批」聚合卡，一步直达；② 「更多」页**首位**就是审批中心，且**保留角标**，路径是「Tab5 → 第一格」，比多数二级页还短。
4. **可回退**：若上线后数据显示审批点击量显著高于待办，只需交换 3/4 槽位的路由映射，不涉及数据模型与路由 slug。

**被下沉的功能与理由**

| 功能 | 下沉理由 |
|---|---|
| 审批中心 | 已在工作台有聚合卡；事件驱动，非每日必达 |
| 谈心谈话 | 高频但**适合现场记录后补录**，且可从学生详情「发起谈心」直达，不依赖一级入口 |
| 通知发布 | 编辑长文**更适合桌面**；移动端只做查看/撤回 |
| 模板汇总库 | 下载/批量操作适合桌面；移动端只做浏览 + 单文件下载 |
| 实用工具 | iframe 内嵌工具在小屏可用性差（H5），移动端只保留入口并提示「建议在电脑使用」 |
| 用户管理 / 访问日志 | 管理员专属、低频，按 `role === 'admin'` 显隐 |

## 7. 卡片字段层级表（学生卡 · 三层）

> 设计依据：辅导员查学生的第一诉求是「这是谁、哪个班、归不归我、有没有风险」；隐私字段低频且敏感，需二次操作。

| 层级 | 字段 | 字号/字重 | 出现条件 | 说明 |
|---|---|---|---|---|
| **L1 首屏必读** | 姓名、**班级·专业**、主责/共管标识 | 16–17px / 600 | 始终 | 最高对比（对白 10.49:1）；姓名旁跟 42px 头像 |
| **L2 一眼可见** | 学号、最近谈心时间、**预警状态（颜色+图标+文字）**、在读状态 | 13–14px / 400 | 预警仅在有预警时出现 | 预警 chip 右对齐，绝不折行 |
| **L3 详情内 / 可折叠** | 宿舍、班主任、辅导员、**本人手机（默认脱敏）**、**父母姓名与手机（默认脱敏）** | 13–14px / 400 | 详情页；列表页以单行摘要呈现掩码手机号 | 掩码格式 `158****1094`；明文需点「查看」 |
| **操作区** | 拨号 / 短信（列表）；拨号 / 短信 / 发起谈心 / 发通知 / 标记预警（详情） | 图标 18–20px | 始终 | 热区 ≥44×44，间距 ≥8px；卡内按钮阻止冒泡 |

**其他模块的卡片字段层级（简表）**

| 卡片 | 主字段 | 次字段 | 操作区 |
|---|---|---|---|
| 预警卡 | 学生姓名 + **级别 chip（三编码）** | 班级·类型·时间·处理状态·事由·措施 | 记录措施 / 去处置 / 确认销号 |
| 待办卡 | 事项标题 + **优先级** | 截止时间（逾期带文字）、关联学生、来源 | 44px 打卡框 |
| 审批卡 | 事项类型 + 申请人 | 班级·学号·摘要·提交时间·状态 | 去审批 |
| 数据卡（工作台） | 大数字（26px, tabular-nums） | 指标名（12px） | 整卡跳对应模块 |
| 通知卡 | 标题 + **状态 tag** | 类型·范围·时间·置顶标识 | 查看 / 编辑 / 撤回 |

## 8. 组件清单

| 组件 | 移动端规格 | 备注 |
|---|---|---|
| 顶栏 `m-topbar` | 48px + `env(safe-area-inset-top)`；返回 / 标题 / 铃铛(角标) | **必须补顶部安全区**（参考规范已知缺口 6） |
| 唯一滚动容器 `m-scroll` | `flex:1; overflow-y:auto; overflow-x:hidden` | 全屏只有一个 |
| 底部 TabBar | 56px + `env(safe-area-inset-bottom)`；5 项，图标 22px + 11px 文字 | 位于滚动容器**兄弟层**；禁止 `fixed` |
| 搜索框 `search-field` | 44px / 16px；前置图标绝对定位 + `padding-left:36px` | 常驻列表顶部 |
| 底部抽屉 Sheet | 圆角 `22px 22px 0 0`；把手 40×4px（纯视觉）；`max-height:92dvh` | 入 240ms / 出 160ms；关闭靠遮罩 / × / 取消 |
| 居中确认框 Dialog | 圆角 16px；danger 主按钮 | 不可逆操作必用 |
| Toast | 顶部居中，z-2000，停留 2.6s 后 320ms 淡出 | success / error / info |
| 按钮 `btn` | 44px（底栏主按钮 48px）；按压 `scale(.97)` / 80ms | — |
| 输入 `inp` | 44px / **16px**；焦点环 `0 0 0 3px var(--m-ring)` | 低于 16px iOS 会强制放大整页 |
| 复选框 `box` | 本体 18×18，热区 44×44；`accent-color` 主色 | — |
| 单选 `radio` | 44px pill，选中圆点填充主色 | 审批通过/驳回 |
| chip | 可点 chip `min-height:44px`；展示 tag 22px | 筛选/级别/状态 |
| 折叠 `details.fold` | summary `min-height:44px`；`::marker` 隐藏 | 已完成待办 |
| 吸附操作条 `m-actionbar` | `position:sticky; bottom:0; z-index:40` | **禁止 fixed** |
| 脱敏行 `frow.sec` | 掩码 ↔ 明文；「查看 / 隐藏」按钮 44px | 见 §9.4 |
| 头像 `ava` | 42px（列表）/ 52px（详情）；品牌渐变 | 预警学生可用级别色渐变 |
| 宫格 `gcell` | 3 列，88px 高，图标 40px 圆角方块 | 更多页 |

**状态清单**

| 组件 | 状态 |
|---|---|
| 卡片 | 默认 / 按压（`scale .97`）/ 已解除（虚线·去阴影）/ 空态（虚线框） |
| 按钮 | 默认 / 按压 / 禁用（`opacity:.5; pointer-events:none`）/ 提交中（文案切换） |
| 输入 | 默认 / 聚焦（焦点环）/ 错误（就近红字，`min-height:18px` 常驻）/ 禁用 |
| 复选框 | 未选 / 已选 / 聚焦（焦点环） |
| 预警 | 待处理 / 处理中 / 已解除 × 红 / 橙 / 黄 |
| 待办 | 未完成 / 已完成 / 已逾期（+文字标识） |
| 审批 | 待审批 / 已通过 / 已驳回 |
| 通知 | 草稿 / 已发布 / 已撤回（本期原型未出屏） |
| 页面 | 加载中（纯文案「加载中…」）/ 空态 / 错误（错误卡，绝不白屏）/ 无权限（Toast + 跳工作台） |
| 脱敏 | 掩码（默认）/ 明文（点击查看）/ 自动回隐（离开页面） |

## 9. 开发落地注意事项

### 9.1 ⭐ 底部吸附一律 `sticky`，禁止 `fixed`

> 参考规范已记录故障：滚动容器 `.content` 带 `transform`（本项目页面入场动画也是 `translateY`），会成为 `position: fixed` 的**包含块**，导致吸附层跟着内容一起滚走。

```css
/* ✅ */
.m-actionbar { position: sticky; bottom: 0; z-index: 40; }
.m-tabs      { position: sticky; top: 0;    z-index: 5;  }
/* 若浮层需锚在吸附栏上方：绝对定位 + bottom:100%（父级给 position:sticky） */
.m-morph     { position: absolute; left:0; right:0; bottom:100%; z-index:2; }

/* ❌ */
.m-actionbar { position: fixed; bottom: 0; }
```

配套纪律：
- **滚动容器唯一**：每页只有 `.m-scroll` 一个滚动容器，遮罩/浮层/吸附全以它为基准。
- **TabBar 放在布局外壳**（`BasicLayout`）里，作为滚动容器的兄弟节点；若必须放进滚动容器，用 `position:sticky; bottom:0; z-index:50`。
- 页面入场动画若在 `.m-scroll` 上加 `transform`，务必再次回归验证吸附条不漂移。

### 9.2 ⭐ 输入字号 ≥16px

- 所有 `input` / `textarea` / `select` 的 `font-size: 16px`（**红线**）。低于此值 iOS Safari 聚焦时会强制放大整个页面，出现「点一下输入框页面就炸开」的体感。
- AntD 5 没有对应 token，必须落 CSS 兜底：

```css
@media (max-width:768px){
  .ant-input, .ant-input-number-input, .ant-picker-input > input,
  .ant-select-selection-search-input, textarea.ant-input { font-size:16px !important; }
}
```

- 视觉紧凑靠 `min-height:44px` + `padding:10px 12px` 实现，**绝不靠缩字号**。
- `controlHeight: 44` / `controlHeightSM: 44` / `controlHeightLG: 48` 三个 token 一起改，避免 AntD 组件高低不齐。

### 9.3 ⭐ 安全区

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
<meta name="color-scheme" content="light" />
```
- `viewport-fit=cover` 是 `env()` 生效的**前提**。
- `color-scheme: light` 防止 Android Chrome「Auto Dark」在夜间强制压暗（参考规范原则 6）。

| 位置 | 必须接 |
|---|---|
| 顶栏 | `padding-top: env(safe-area-inset-top)`（**参考规范缺口 6：原 `.topbar` 漏接，刘海屏被状态栏遮挡**） |
| 底部 TabBar | `padding-bottom: env(safe-area-inset-bottom)` |
| 底部吸附条（若为屏幕最底元素） | `padding-bottom: calc(10px + env(safe-area-inset-bottom))` |
| 内容区底部（无 TabBar 页） | `padding-bottom: calc(16px + env(safe-area-inset-bottom))` |
| 抽屉底部按钮区 | `padding-bottom: calc(16px + env(safe-area-inset-bottom))` |

建议用 `@supports` 包裹老浏览器降级；`env()` 第二参数给 `0px` 兜底。

### 9.4 ⭐ 脱敏实现要点

**展示规则**

| 场景 | 形态 |
|---|---|
| 列表卡 | **始终掩码**，不提供「查看」（列表是高频扫视场景，不给明文入口） |
| 详情页 · 默认 | 掩码 `158****1094` + 右侧「查看」按钮（44px 热区） |
| 详情页 · 点击查看 | 明文 `158 8872 1094`，按钮变「隐藏」，行底黄色提示「已展示明文 · 离开本页自动回隐」 |

**实现要点**
1. **掩码在服务端/接口层完成更安全**：理想是后端只返回掩码串，明文走单独的「申请查看」接口并记录审计日志；若后端暂不支持，前端掩码必须保证**明文不出现在 DOM 的初始渲染**里（不要 `data-phone="138..."` 挂在属性上）。
2. **自动回隐**：在路由离开（`useEffect` cleanup / `beforeunload`）与页面隐藏（`visibilitychange`）时重置 `revealed` 状态；不要把「已查看」写进 localStorage。
3. **一个字段一个状态**：本人手机、父亲、母亲各自独立 `revealed`，互不影响（原型即如此）。
4. **掩码格式统一**：手机号 `前3 + **** + 后4`；姓名不掩码（业务上需要确认人）；家庭关系保留称谓。
5. **禁止**：截屏/长按复制不受控（可给明文区域加 `-webkit-touch-callout:none`）；明文写在 URL / 日志 / 埋点里。

**原型中的纯 CSS 实现**（供参考）

```css
.frow .plain{display:none}
.frow:has(.seck:checked) .plain{display:inline}
.frow:has(.seck:checked) .mask{display:none}
.seck:checked ~ .sw-v{display:none}      /* 查看 → 隐藏 */
.seck:checked ~ .sw-h{display:inline}
```

### 9.5 其他工程纪律

| 项 | 要求 |
|---|---|
| 断点 | 仅 `≤768 / ≤576 / ≤380`；桌面 `>768px` **零改动**（不新增媒体查询覆盖桌面类） |
| 路由 | 不改 slug（`/students`、`/warnings`…）；只新增移动端呈现层外壳 |
| 作用域 | 页面级样式必须以 `.page-xxx` 之类作用域类限定，避免污染全局 `.card` / `.stat-*` |
| 长文本 | `overflow-wrap:anywhere; word-break:break-word` + **父级 `min-width:0`**（缺 `min-width:0` 不参与 flex 收缩，仍会横向冲出）；右侧短文本区 `white-space:nowrap` |
| 横向滚动 | 全局禁止；`.frame` / 卡片父级必须 `min-width:0` |
| 视口高度 | 一律 `100dvh`，不用 `100vh` |
| 数字 | `font-variant-numeric: tabular-nums`（数据卡、学号、时间、计数） |
| 语义色 | 只走 token，禁止裸 hex；预警三级必须「颜色 + 图标 + 文字」 |
| 动效 | ≤240ms；离场快于入场；`prefers-reduced-motion` 下 `animation:none !important` 落到终态 |
| 按压 | 全站 `:active` + `transform:scale(.97)` + `80ms`，**不用 touch 事件** |
| 图标 | 统一 stroke 风格 SVG，**显式 `width`/`height`**（缺省会按 300×150 渲染成巨大图形）；**禁止 emoji** |
| 无障碍 | 图标按钮必补 `aria-label`；开关类补 `role="switch"` + `aria-checked`；所有插值过转义 |
| 状态 | 加载中=纯文案；空态=虚线框；错误=错误卡（绝不白屏）；无权限=Toast + 跳工作台 |
| 不可逆操作 | 销号 / 驳回 / 撤回 / 退出登录 → `confirmDialog({ danger:true })` |
