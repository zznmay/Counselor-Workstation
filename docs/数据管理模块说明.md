# 数据管理模块（备份 / 恢复 / 迁移）

> 挂载位置：侧边栏「系统管理 → 数据管理」（与用户管理 / 角色管理 / 访问日志同层级，仅系统管理员可见）。
> 设计范式来源：`学生考勤平台git/docs/数据管理技术架构-可复用.md`，按本平台 Express + SQLite + React/antd 架构落地。

---

## 1. 沿用的架构约定

| 层 | 本模块实现 | 沿用的现有约定 |
|----|-----------|----------------|
| 服务端业务逻辑 | `server/lib/datamgmt.js` | 与 `lib/permissions.js`、`lib/scope.js` 同风格：只做业务与存储，不接触 req/res |
| 服务端控制器 | `server/routes/data.js` | 与 `routes/logs.js` 同风格：`authMiddleware` + `adminOnly`，只解析请求 / 组装响应 |
| 数据访问 | `dbx.get/all/run/withTransaction` | `server/lib/db.js` 既有封装（无 `.prepare` 直调，事务用 `withTransaction`） |
| 建表 | `SCHEMA_STATEMENTS` 内追加 `CREATE TABLE IF NOT EXISTS` | 与既有表同段、同注释风格，老库启动幂等 |
| 路由注册 | `server/index.js`：`api.use('/data', require('./routes/data'))` | 与 `/logs`、`/roles` 同段注册 |
| 前端请求 | `src/api/data.ts` 走 `@/api/request` 的 `request<T>()` | 统一 BaseURL、令牌注入、错误消息提取 |
| 前端页面 | `src/pages/admin/data.tsx`（桌面）+ `dataMobile.tsx`（移动） | `PageHeader` + `useList` + antd Table/Modal/Form/Popconfirm；≤768px 视口分发 |
| 路由 | `src/router/index.tsx`：`/admin/data` 包 `RequireAdmin` | 与 `/admin/users|roles|logs` 同口径 |
| 菜单 | `src/layouts/BasicLayout.tsx` 系统管理子菜单第 4 项 | `DatabaseOutlined` 图标、`/admin/data` key、`TITLES` 补标题 |
| 权限标识 | 不在 `APP_MODULES` 注册 | 与既有「系统管理（用户/角色/日志）」一致：属系统级能力，仅 `admin`，不通过角色权限下发 |
| 常量字典 | `src/constants/index.ts` 追加 `BUNDLE_KINDS` 等 | 与 `TODO_TYPES`、`TALK_TYPES` 同段同风格；两端 `BundleKind` 与服务端 `BUNDLE_KINDS` 同序同名 |

## 2. 数据模型（新增 3 张表，启动时幂等建表）

| 表 | 用途 | 关键字段 |
|----|------|----------|
| `dataBundles` | 数据包索引（包体落盘 `data/backups/<fileName>`） | `kind / label / note / fileName(唯一) / sizeBytes / sha256 / schemaVersion / counts(JSON) / createdBy / createdAt` |
| `dataSettings` | 键值配置（自动备份策略） | `key / value(JSON) / updatedAt / updatedBy` |
| `dataOplog` | 数据管理操作日志 | `ts / actor / action / summary`（环形保留最近 500 条） |

**初始化说明**：三张表均为 `CREATE TABLE IF NOT EXISTS`，老库启动自动补齐、不重建不清理业务数据（延续「数据安全铁律」）。
自动备份首次读取时回落到默认值 `{ enabled:false, intervalHours:24, keep:10 }`，无需手工初始化。

**参与导出的业务表（`EXPORT_TABLES`，22 张）**：
`users / roles / userRoles / students / studentCounselors / grades / classes / classCounselors / conversations /
mentalHealth / mentalInterviews / mentalInterviewTemplates / mentalLevelLogs / warnings / notices / approvals / todos /
templateCategories / templateFiles / csScheduler / accessLogs / loginAttempts`

> `dataBundles / dataSettings / dataOplog` 不进包：避免恢复时自引用覆盖，也保证恢复后仍可追溯「谁在什么时候恢复过」。

## 3. 数据包（Bundle）格式与校验

```json
{
  "kind": "手动备份",
  "label": "学期初全量备份",
  "schemaVersion": 1,
  "appVersion": "1.0",
  "exportedAt": "2026-10-20T07:30:00.000Z",
  "exportedBy": "admin",
  "source": "counselor-workbench",
  "counts": { "students": 24, "...": 0 },
  "manifest": [{ "table": "students", "count": 24, "sha256": "..." }],
  "tables": { "students": [ ... ] }
}
```

- **manifest 强校验**：导入侧逐表复核「条数 + 行内容 sha256」，任一不符即整体拒绝（篡改包实测被 400 拦截）；
- **宽松降级**：历史包缺某张表时按 0 条处理，不阻断；无 manifest 记录的表按宽松处理；
- **原子写**：`tmp + rename` 落盘，杜绝半个 JSON。

## 4. 字典项（前后端同序同名，改一处需同步另一处）

| 字典 | 取值 | 位置 |
|------|------|------|
| 数据包类型 `kind` | `手动备份` / `自动备份` / `恢复前快照` / `迁移包` / `上传包` | `server/lib/datamgmt.js` ↔ `src/constants/index.ts` |
| 可手工创建的类型 | `手动备份` / `迁移包` | `BUNDLE_CREATE_KINDS` |
| 自动备份间隔 | `1 / 2 / 4 / 6 / 12 / 24` 小时 | `AUTO_BACKUP_INTERVALS` |
| 保留份数 | `3 – 30` 份（环形保留，仅清理自动备份） | `AUTO_BACKUP_KEEP_MIN/MAX` |
| 恢复确认短语 | `恢复` | `RESTORE_CONFIRM_PHRASE` |
| 上传体积上限 | 15MB（受 `express.json` 20mb 限制） | `BUNDLE_UPLOAD_MAX_BYTES` |

## 5. 接口清单（全部 `adminOnly`）

```
GET    /api/data/overview                 总览（表条数/库体积/备份概况/自动备份/最近日志）
GET    /api/data/counts                   各表条数（与总览同口径）
GET    /api/data/bundles                  列表（keyword/kind/起止日期/page/pageSize/sortBy/sortOrder）
POST   /api/data/bundles                  创建备份（label 必填，kind 默认手动备份）
PATCH  /api/data/bundles/:id              编辑标签与备注（包体内容不可变）
DELETE /api/data/bundles/:id              删除（同时清理落盘文件）
GET    /api/data/bundles/:id/download     下载包体
POST   /api/data/bundles/upload           上传数据包（base64，可 gzip）→ 校验后登记
POST   /api/data/restore/preview          恢复预检（不落盘，返回校验明细与条数 diff）
POST   /api/data/restore                  恢复（confirm 必须为「恢复」，先自动前快照）
GET    /api/data/autobackup               自动备份策略
POST   /api/data/autobackup               保存策略（并重新调度）
POST   /api/data/autobackup/run           立即执行一次（内容签名未变则跳过写包）
GET    /api/data/oplog                    操作日志（默认 50 条，上限 500）
```

**恢复三段式（防误操作，缺一不可）**：预检（不落盘）→ 确认短语「恢复」→ 恢复前自动生成「恢复前快照」包；误操作后可再恢复该快照回滚。

## 6. 自动备份

- 配置持久化在 `dataSettings.autoBackup`；进程启动时 `scheduleAuto()` 按配置链式调度（`setTimeout` + `unref()`，不阻塞退出）；
- **内容签名去重**：对业务表整体算 sha256，签名未变则跳过写包、只刷新 `lastRunAt`；
  ⚠️ `accessLogs / loginAttempts` 属审计流水（每次请求都在增长），**不计入签名**（但仍进包），否则去重永远不生效；
- 环形保留：仅清理「自动备份」类型，保留最近 `keep` 份，手动包与恢复前快照不受影响。

## 8. 验证结果

- 服务端接口：隔离库 30/30（含篡改包拒绝、越权 403、确认短语错误被拒、恢复后数据复原、签名去重）；

- `tsc --noEmit` 0 错、`vite build` 通过。

## 9. 已知限制与后续建议

1. **上传为单请求 base64**（上限 15MB）。若后续部署网关对上行体积敏感，可照考勤平台范式增加「分片 + 逐片重试 + 整包 sha256 对账」通道。
2. **附件目录 `data/uploads`（模板文件）不进包**。当前备份覆盖全库业务数据；如需整机迁移，请同步拷贝该目录，或后续扩展为自包含容器（需引入 zip/tar 能力）。
3. **恢复粒度**：目前只支持整库替换。如需单表/单学生回滚，可在 `applyBundle` 之外增加按表选择的应用范围。
4. **异地容灾**：可定时把最新包下载后归档到校内存储，目前保留策略依赖服务端本地目录。
