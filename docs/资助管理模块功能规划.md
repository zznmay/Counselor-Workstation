# 资助管理模块功能规划（困难生认定）

> 版本：v0.1（功能规划）
> 日期：2026-10-22
> 分支：`dev_资助管理模块创建`
> 范围：首版仅覆盖困难生认定；奖助项目、审批流转、在线材料与发放不在本期范围。

## 1. 背景与目标

学校现有辅导员工作台已覆盖学生名册、谈心谈话、预警管理、心理健康、班级管理、寝室管理等日常业务，但家庭经济困难学生的认定信息仍散落在名册备注、预警记录和线下表格中，缺少统一、可按学年追溯的困难生档案。

本模块的目标是：

1. 建立按学年维护的困难生认定档案，回答“谁是困难生、困难程度如何、认定是否有效、依据是什么、何时由谁变更”。
2. 提供认定状态与年度复核的跟踪能力，避免认定过期或漏复核。
3. 提供困难生对象统计与名册/汇总导出，支撑院内工作分析与上报。
4. 为后续奖助学金、助学贷款、勤工助学等项目提供资格数据底座。

## 2. 现状与设计约束

| 现状 | 影响 |
|---|---|
| 仓库尚无资助模块、认定专表或相关设计文档 | 需要从零建立模块，并按现有业务模块规范接入 |
| `students` 表没有家庭经济等级、困难类型、认定学年等字段 | 不能把认定信息塞进学生表，需要独立建模 |
| 学生名册支持 Excel 导入，学生字段可能被批量覆盖 | 认定历史不能依赖学生表字段，否则会丢失 |
| `approvals` 表是通用审批表，仅含类型、摘要、详情与状态，且对应页面已删除 | 不适合承载按学年留档、可多次变更的困难认定档案 |
| 现有模块以“列表 + 筛选 + 弹窗/抽屉 + 导入导出”为主 | 新模块沿用同一交互与接口范式，降低维护成本 |
| 桌面端与移动端共用路由，页面内按视口分流 | 需同时规划桌面端完整能力与移动端查询/维护能力 |
| 数据管理负责全库备份、恢复与迁移 | 新表必须纳入数据包，否则备份会缺表 |

设计约束：

- 不修改 `students` 表；认定档案通过 `studentId` 逻辑关联学生名册，不建外键。
- 一个学生一个学年最多一条“有效”认定记录；历史学年分别留档，不覆盖。
- 状态变更必须留痕；取消、调级、缩短有效期等敏感操作必须填写原因。
- 困难认定属于敏感数据，读写均按带班范围收口，管理员全量。
- 首版不引入审批流与附件存储，避免范围膨胀。

## 3. 模块定位与范围

### 3.1 模块定位

在网页端左侧导航「业务办理」分组新增「资助管理」，首版聚焦**困难生认定**：

- 按学年建立、维护、复核困难生认定档案；
- 记录困难等级、困难类型、认定依据与有效期；
- 支持取消、重新认定、学年结转与批量维护；
- 提供困难生统计与 Excel 导入导出；
- 为后续资助项目提供可复用的资格数据。

### 3.2 首版范围

- 困难生认定对象档案（新增、编辑、取消、重新认定、批量维护）
- 困难等级与困难类型管理
- 认定学年、有效期、学年复核与结转
- 认定状态变更与全程变更记录
- 多条件查询、困难生统计、Excel 导入导出
- 桌面端与移动端基础入口
- 模块权限、带班数据范围、访问审计

### 3.3 首版不包含

- 奖助学金项目、名额分配、申请、评审、公示、发放
- 助学贷款、勤工助学、学费减免、绿色通道
- 审批流、多级审核、消息通知
- 证明材料上传、预览、下载
- 与财务系统、上级资助平台对接
- 自动认定规则或学生端申请入口

## 5. 功能清单

### 5.1 资助对象信息管理

| 功能点 | 用途 | 主要操作流程与关键规则 |
|---|---|---|
| 认定档案列表 | 查看和维护困难生档案 | 按学年进入；列表展示学生、班级、等级、类型、有效期、状态、最近变更；支持分页与筛选；默认展示当前学年。 |
| 从学生名册新增认定 | 建立单人认定档案 | 点「新增认定」→ 按姓名/学号检索学生（检索范围受带班权限限制）→ 选择学生 → 填写学年、困难等级、困难类型、认定日期、有效期、认定依据 → 保存，状态直接为「已认定」。同一学生同一学年已有有效记录时禁止重复新增，提示先取消或编辑原记录。 |
| 编辑认定档案 | 维护等级、类型、期限、依据 | 可修改困难等级、困难类型、认定日期、有效期、认定依据、备注；认定日期与有效期精确到月份（YYYY-MM）；等级调整或缩短有效期必须填写原因；每次修改写入变更时间线。 |
| 取消认定 | 终止当前认定并保留历史 | 填写取消原因 → 状态改为「已取消」；记录不物理删除；列表可筛选查看历史。 |
| 重新认定 | 恢复已取消学生的资格 | 对已取消记录执行「重新认定」→ 新建一条认定记录，`previousId` 指向原记录 → 新记录状态为「已认定」；原记录保持「已取消」。 |
| Excel 批量导入 | 批量建立或修正档案 | 下载模板 → 选择文件 → 前端解析校验 → 预览成功行/失败原因 → 确认提交 → 后端按「学号+学年」upsert，事务写入 → 展示新增/更新/跳过/失败统计，失败明细可导出。必填：学号、学年、困难等级；学号必须存在于名册且在当前教师带班范围；姓名、班级、年级由系统按学号从学生名册自动带出，无需在表格中填写；文件内学号不得重复；等级、日期、有效期必须合法；日期支持 `YYYY-MM`、`YYYY年M月`、`YYYY年M月份`、`YYYY/M`、`YYYY.M`、`YYYYMM`、`YYYY-MM-DD` 等写法，统一归一为 `YYYY-MM` 存储。 |
| 批量维护 | 提高批量操作效率 | 勾选多条 → 选择动作（批量调级 / 批量取消 / 批量续期 / 批量复核确认）→ 填写统一原因 → 逐条鉴权并执行 → 返回成功数与失败明细；越权或非法记录单条失败，不影响其它行。 |
| 学年复核与结转 | 新学年延续认定工作 | 选择源学年与目标学年 → 预览「在读且已认定」名单 → 生成目标学年「待复核」记录（继承等级、类型，重置有效期）→ 逐条或批量确认、调级、取消。重复执行跳过已存在记录，不覆盖历史学年。 |

### 5.2 认定进度与状态变更

| 功能点 | 用途 | 主要操作流程与关键规则 |
|---|---|---|
| 状态总览 | 快速掌握本学年认定情况 | 顶部统计条展示：已认定人数、待复核人数、30 天内到期人数、已取消人数；支持点击卡片带入筛选条件下钻列表。 |
| 年度复核进度 | 跟踪新学年认定确认进度 | 展示「已确认 / 应复核」进度与百分比；列出未确认名单；支持批量确认。 |
| 档案详情与时间线 | 查看完整认定依据与变更轨迹 | 详情抽屉/全屏页展示学生摘要、认定信息、关联预警/谈话（只读）、变更时间线（新增、编辑、调级、取消、复核、结转、导入，含操作人、时间、原因）。 |
| 状态变更 | 维护认定生命周期 | 详情页按合法迁移展示操作项；非法迁移由服务端拒绝；取消、调级、缩短有效期必须填写原因；变更成功后刷新列表与统计。 |
| 到期提示 | 防止认定过期未处理 | 列表对 30 天内到期、已过期记录高亮；筛选支持「即将到期」「已过期」。 |

### 5.3 统计查询与报表

| 功能点 | 用途 | 主要操作流程与关键规则 |
|---|---|---|
| 多条件查询 | 快速定位对象 | 关键词（姓名/学号/班级）、学年、困难等级、困难类型、状态、班级多选、年级、有效期状态；筛选条件可组合、可重置；统计与导出沿用当前筛选口径。 |
| 困难生统计概览 | 掌握总体规模与结构 | 指标：本学年认定总人数、三档等级人数、认定率（已认定人数/范围内在读学生数）、待复核数、30 天内到期数。 |
| 分布统计 | 支持工作分析与上报 | 按困难等级、年级、班级、困难类型、生源地分布；展示 Top N 班级与各类型占比；支持按学年对比；使用现有 StatCard + 纯 CSS 条形图，不引入图表库。 |
| 名册导出 | 导出当前筛选对象 | 导出学生姓名、学号、性别、年级、班级、学年、困难等级、困难类型、认定日期、有效期、状态、认定依据（可选）、备注；认定日期与有效期按月份导出；前端懒加载 xlsx 生成，文件名含学年与日期。 |
| 汇总报表导出 | 用于院内汇总与归档 | 生成两个 sheet：「班级×困难等级」交叉汇总表；「困难类型统计表」。数据口径与页面筛选一致。 |

## 6. 状态模型

### 6.1 状态集合

| 状态 | 说明 |
|---|---|
| `待复核` | 新学年结转生成，等待教师确认；此时不视为已认定生效 |
| `已认定` | 当前学年有效认定 |
| `已取消` | 认定被取消，终态，保留历史 |
| `已过期` | 展示态：`已认定` 且 `validTo < 今日`；不落库，避免定时任务 |

### 6.2 合法迁移

```
新增 / 导入 ─────────────▶ 已认定
学年结转 ───────────────▶ 待复核
待复核 ──确认───────────▶ 已认定
待复核 ──取消───────────▶ 已取消
已认定 ──取消───────────▶ 已取消
已认定 ──到期(自动展示)──▶ 已过期
已取消 ──重新认定────────▶ 新记录（已认定，previousId 指向原记录）
```

规则：

- 已取消、已过期记录不能原地恢复；必须新建记录。
- 同一学生同一学年只允许一条 `待复核`/`已认定` 记录，由数据库部分唯一索引兜底。
- 不做审批节点，状态由具备该模块权限且满足带班范围的教师直接维护。
- 前端不提供物理删除；误录记录应通过取消留痕，必要时由管理员在数据管理中处理。

### 6.3 必填原因

| 操作 | 是否必须填写原因 |
|---|---|
| 取消认定 / 批量取消 | 是 |
| 调整困难等级 / 批量调级 | 是 |
| 缩短有效期 / 批量续期（缩短时） | 是 |
| 结转后调整等级 | 是 |
| 重新认定 | 是 |
| 编辑困难类型、认定依据、备注 | 否 |
| 复核确认（等级不变） | 否 |

## 7. 数据模型草案

> 表名与模块 key 采用 `funding`，便于后续扩展奖助项目。以下为详细设计阶段的基线，最终字段以实现为准。

### 7.1 `fundingIdentifications`（困难生认定档案）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 主键 |
| studentId | TEXT NOT NULL | 逻辑关联 `students.id`，不建外键 |
| academicYear | TEXT NOT NULL | 学年，如 `2026-2027` |
| level | TEXT NOT NULL | 特别困难 / 困难 / 一般困难 |
| difficultyTypes | TEXT NOT NULL DEFAULT '[]' | 困难类型 JSON 数组：低保家庭、特困供养、脱贫家庭、残疾学生、孤儿、突发严重困难、其他 |
| status | TEXT NOT NULL | 待复核 / 已认定 / 已取消 |
| identifiedAt | TEXT | 认定月份，YYYY-MM |
| validFrom / validTo | TEXT | 有效期起止月份，YYYY-MM |
| basis | TEXT | 认定依据（文字） |
| remark | TEXT | 备注 |
| source | TEXT NOT NULL | manual / import / rollover |
| previousId | TEXT | 重新认定时指向原记录 |
| createdBy / createdAt | INTEGER / TEXT | 创建人、创建时间 |
| updatedBy / updatedAt | INTEGER / TEXT | 最近修改人、时间 |
| cancelledAt | TEXT | 取消时间 |
| cancelReason | TEXT | 取消原因 |

约束与索引：

- 部分唯一索引：`(studentId, academicYear) WHERE status IN ('待复核','已认定')`，保证同一学年仅一条有效记录。
- 普通索引：`(academicYear, status)`、`(academicYear, level)`、`(studentId)`、`(validTo)`。

### 7.2 `fundingIdentificationLogs`（认定变更记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 主键 |
| identificationId | TEXT NOT NULL | 关联认定档案 |
| studentId | TEXT NOT NULL | 冗余便于按学生查询时间线 |
| action | TEXT NOT NULL | create / update / level_change / status_change / review / cancel / rollover / import |
| fromStatus / toStatus | TEXT | 状态变化 |
| fromLevel / toLevel | TEXT | 等级变化 |
| reason | TEXT | 变更原因 |
| operatorId | INTEGER | 操作人 ID |
| operatorName | TEXT | 操作人姓名快照 |
| createdAt | TEXT | 操作时间 |

索引：`(identificationId, createdAt DESC)`、`(studentId, createdAt DESC)`。

### 7.3 为什么不修改 `students` 表

- 认定是按学年反复发生的敏感档案，学生表字段无法保存历史。
- 名册支持 Excel 导入，直接加字段会被覆盖或产生不一致。
- 独立表可支持多年追溯，后续奖助项目可按认定记录判断资格。
- 学生删除后认定历史保留，与现有预警/审批“逻辑关联、不建外键”的口径一致。

### 7.4 数据管理接入

- `server/lib/datamgmt.js` 的 `TABLE_LABELS` 增加「困难生认定」「认定变更记录」。
- `EXPORT_TABLES` 增加两张表；`SCHEMA_VERSION` 由 2 递增至 3。
- 恢复旧版本数据包时需兼容缺失新表（按空表处理并提示），避免旧备份不可恢复。

## 8. 接口草案

统一前缀 `/api/funding`，全部经过 `authMiddleware + requirePermission('funding')`。

| 方法 | 路径 | 用途 | 权限/口径 |
|---|---|---|---|
| GET | `/identifications` | 分页列表与筛选 | 读范围 `sensitiveScope` |
| GET | `/identifications/:id` | 档案详情 + 学生摘要 + 变更日志 + 关联预警/谈话 | 读范围 |
| POST | `/identifications` | 新增认定 | `canManageStudent` + 同学年查重 |
| PUT | `/identifications/:id` | 编辑档案 | `canManageStudent`；敏感变更要求 reason |
| POST | `/identifications/:id/status` | 确认复核 / 取消 / 调级 | `canManageStudent`；服务端校验合法迁移 |
| POST | `/identifications/batch` | 批量调级/取消/续期/复核确认 | 逐条鉴权，返回成功数与失败明细 |
| GET | `/rollover/preview` | 学年结转预览 | 读范围；返回可结转/跳过名单 |
| POST | `/rollover` | 生成目标学年待复核记录 | 事务写入，重复记录跳过 |
| POST | `/identifications/import` | 批量导入（前端解析后提交行数据） | 逐行 `canManageStudent`；整体事务；返回新增/更新/跳过/失败 |
| GET | `/stats` | 统计概览与分布 | 与列表同筛选口径 |
| GET | `/identifications/:id/logs` | 分页查询变更时间线 | 读范围 |

导出不新增服务端文件接口：复用现有前端分页全量拉取 + xlsx 生成模式（参考 `src/utils/dormExport.ts`），保证统计口径与列表一致。

## 9. 页面与导航规划

### 9.1 桌面端 `/funding`

- 顶部：PageHeader「资助管理」+ 学年选择器 + 新增认定 / 导入 / 导出。
- 统计区：4–5 张 StatCard（已认定总人数、特别困难、困难、一般困难、待复核/即将到期）+ 分布 MiniBars。
- 筛选区：关键词、学年、等级、困难类型、状态、年级、班级多选、日期区间、更多筛选。
- 列表：学生信息、班级、学年、等级、类型、有效期、状态、最近变更、操作（详情/编辑/取消/重新认定）。
- 详情 Drawer：学生摘要、认定信息、关联预警与资助帮扶谈话（只读）、Timeline 变更记录、状态操作按钮。
- 弹窗/抽屉：新增/编辑、取消原因、导入向导（模板→解析→预览→提交→失败明细）、学年结转向导。
- 导出下拉：认定名册 / 汇总报表。

## 11. 权限与数据安全

- 模块权限：`funding`；无权限用户路由拦截 `/forbidden`，接口返回 403。
- 读取/统计/导出：非管理员按 `sensitiveScope`（档案所属学生在当前教师带班班级内）；管理员全量。
- 写入/批量/导入：逐学生校验 `canManageStudent`；管理员全量。
- 所有写操作调用 `logAccess` 记录访问日志；业务变更另写认定变更日志表。
- 学生状态为休学/退学：详情与列表给出提示，但不自动取消认定，由教师判断处理。
- 移动端同样遵守模块权限与带班范围，不因入口不同放宽数据范围。

## 13. 验收要点

- `npm run typecheck`、`npm test` 通过；桌面/移动导航与直达 URL 正常。
- 无权限角色访问 `/funding` 跳转 `/forbidden`；教师只能读写带班学生。
- 同一学生同一学年不可重复建立有效认定；非法状态迁移返回 400。
- 取消/调级原因必填；时间线完整；批量操作逐条返回失败明细。
- 导入覆盖空文件、重复学号、非名册学生、非法等级/日期、部分失败、重复导入幂等、事务回滚。
- 学年结转可重复执行且不产生重复记录；统计与列表筛选口径一致；导出防公式注入。
- 数据管理备份→恢复后两张表完整；旧版本数据包恢复有明确兼容/拦截提示。
- 移动端在窄视口下可完成查询、详情、编辑与取消；桌面端功能不受影响。

## 14. 后续详细设计待确认

1. **学年与有效期默认规则**：学年格式 `2026-2027`，认定日期与有效期精确到月，默认有效期 `2026-09` 至 `2027-08`，是否需按学校实际校历调整。
2. **困难类型字典**：首版拟采用“低保家庭、特困供养、脱贫家庭、残疾学生、孤儿、突发严重困难、其他”，是否还需增加地方性类型。
3. **困难等级口径**：是否固定为“特别困难 / 困难 / 一般困难”三档，是否允许学校自定义。
4. **认定率分母**：按“范围内在读学生数”计算，是否排除休学、退学学生。
5. **旧审批数据**：现有 `approvals` 表中少量“助学金申请/奖学金申请/勤工助学”演示数据本期不迁移，后续建设奖助项目时再确定归档方式。
6. **删除策略**：前端不提供物理删除；是否需要为管理员提供“误录删除”能力并强制留痕。
